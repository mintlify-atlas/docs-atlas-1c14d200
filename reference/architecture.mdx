Mixly is structured as a layered application that runs identically in two runtimes — a desktop Electron app and a Chromium browser — with the same renderer-side JavaScript. Understanding how the processes, components, and environment-switching mechanisms fit together is essential before writing any module-level code or extending the IDE.

## Process Model

### Electron mode

In Electron mode, `main.js` is the entry point for the Node.js main process. It calls `createWindow()` on `app.ready`, which creates a `BrowserWindow` instance (a renderer process) and loads `./src/index.html`. Multiple windows can exist simultaneously — each is an independent renderer process with its own JavaScript context.

```js
// main.js — BrowserWindow creation
function createWindow(filePath = null, indexUrl = null) {
    let win = new BrowserWindow({
        show: false,
        minHeight: 400,
        minWidth: 700,
        width: 0,
        height: 0,
        webPreferences: {
            nodeIntegration: true,
            nodeIntegrationInWorker: true,
            contextIsolation: false,
            spellcheck: false
        }
    });

    electron_remote.enable(win.webContents);

    if (indexUrl)
        win.loadURL(indexUrl);
    else
        win.loadFile('./src/index.html');
    // ...
}

app.on('ready', () => {
    if (process.argv.length >= 2) {
        createWindow(process.argv[1]);
    } else {
        createWindow(null);
    }
});
```

Hardware acceleration is disabled on startup (`app.disableHardwareAcceleration()`) to prevent a black-screen flash before the renderer is ready.

### Web mode

In web mode, a Node.js Express server (`static-server/`) serves the application as a static site. The server starts on port 7000 (HTTP) and port 8000 (HTTPS):

```js
// static-server/static-server.js
StaticServer.run = (port) => {
    const app = express();
    app.use(express.static(path.resolve(__dirname, '../')));
    const httpServer = http.createServer(app);
    httpServer.listen(port);
    StaticServer.server = httpServer;
    StaticServer.protocol = 'http';
}
```

The browser loads `index.html`, which includes `common/main.js` — the same bootstrap script used in Electron. Environment detection happens at runtime through `goog.isElectron` (see [Module System](/reference/module-system)).

## Component Hierarchy

The entire UI is composed of `Component` instances. The base `Component` class (`common/component.js`) provides lifecycle hooks (`mountOn`, `onMounted`, `dispose`), an event bus (`bind` / `runEvent`), and jQuery-backed DOM management (`setContent` / `getContent`).

```
App
├── Nav
├── Workspace
│   ├── EditorsManager       (tabbed editor area)
│   │   ├── EditorMix        (.mix / .mil — Blockly canvas + code preview)
│   │   │   └── EditorBlockly  (Blockly canvas, embedded inside EditorMix)
│   │   ├── EditorCode       (.txt, .ino, .json — Monaco/Ace)
│   │   ├── EditorMd         (.md — Markdown preview with Monaco)
│   │   ├── EditorUnknown    (unsupported file type placeholder)
│   │   └── EditorWelcome    (welcome screen)
│   ├── StatusBarsManager    (bottom panel, tabbed)
│   │   ├── StatusBarOutput  (compiler / runner stdout)
│   │   ├── StatusBarSerial  (serial monitor + chart)
│   │   ├── StatusBarFS      (board filesystem)
│   │   ├── StatusBarLibs    (library manager view)
│   │   └── StatusBarAmpy    (ampy MicroPython file transfer)
│   ├── LeftSideBarsManager
│   └── RightSideBarsManager
└── FooterBar
    ├── FooterLayerBoardConfig
    ├── FooterLayerExample
    └── FooterLayerMessage
```

### App

`App` (`common/app.js`) is the root component. Its constructor mounts `Nav`, `Workspace`, and `FooterBar` onto their respective DOM slots from `html/app.html`, registers all nav toolbar buttons, and calls `Serial.refreshPorts()`:

```js
// common/app.js — App constructor (simplified)
class App extends Component {
    constructor(element) {
        super();
        const $content = $(HTMLTemplate.get('html/app.html').render());
        this.setContent($content);
        this.mountOn($(element));
        this.#nav_ = new Nav();
        this.#nav_.mountOn($content.find('.mixly-nav'));
        this.#workspace_ = new Workspace($content.find('.mixly-workspace')[0]);
        this.#workspace_.getEditorsManager().getTabs().addTab({
            name: 'Untitled-1.mix',
            title: 'Untitled-1.mix',
            type: '.mix',
            favicon: 'fileicon-mix'
        });
        this.#footerbar_ = new FooterBar();
        this.#footerbar_.mountOn($content.find('.mixly-footerbar'));
        Serial.refreshPorts();
        if (goog.isElectron) {
            PythonShell.init();
        }
    }
}
```

### Workspace

`Workspace` (`common/workspace.js`) manages the central layout. It owns four child managers and creates resizable drag dividers (`DragH` for vertical split, `DragV` for horizontal splits):

```js
// common/workspace.js — Workspace constructor (simplified)
class Workspace extends Component {
    constructor(element) {
        super();
        this.#statusBarsManager_ = new StatusBarsManager($content.find('.statusbars')[0]);
        this.#statusBarsManager_.add('terminal', 'output', Msg.Lang['statusbar.output']);
        this.#editorsManager_ = new EditorsManager($content.find('.editors')[0]);
        this.#leftSideBarsManager_  = new LeftSideBarsManager($content.find('.left-sidebars')[0]);
        this.#rightSideBarsManager_ = new RightSideBarsManager($content.find('.right-sidebars')[0]);
        this.dragH = new DragH(this.#$dragH_[0], {
            min: '50px',
            startSize: '100%',
            startExitFullSize: '70%'
        });
    }
}
```

`Workspace.getMain()` returns the first registered workspace instance, making it easy to reach the editors from anywhere: `Workspace.getMain().getEditorsManager()`.

### EditorsManager

`EditorsManager` (`common/editors-manager.js`) extends `PagesManager` and manages a tab strip of editor pages. A static `typesRegistry` maps file extensions to editor classes:

```js
// common/editors-manager.js — type registry
this.typesRegistry = new Registry();
this.typesRegistry.register(['.mix', '.mil'], EditorMix);
this.typesRegistry.register(['.txt', '.ino', '.json'], EditorCode);
this.typesRegistry.register('.md', EditorMd);
this.typesRegistry.register('#default', EditorUnknown);
this.typesRegistry.register('#welcome', EditorWelcome);
```

When a tab is activated, `EditorsManager` pushes the editor's toolbar buttons into the `Nav` component's center editor-buttons slot.

### StatusBarsManager

`StatusBarsManager` (`common/statusbars-manager.js`) also extends `PagesManager` and manages the bottom panel. It holds its own type registry for panel pages and exposes `show()` / `hide()` / `toggle()` methods wired to the `DragH` drag divider. It emits `show` and `hide` events that the workspace listens to:

```js
// common/workspace.js — drag <-> statusbar wiring
this.#statusBarsManager_.bind('show', () => this.dragH.show(Drag.Extend.NEGATIVE));
this.#statusBarsManager_.bind('hide', () => this.dragH.hide(Drag.Extend.NEGATIVE));
```

### Nav

`Nav` (`common/nav.js`) renders a toolbar with three zones: `LEFT` (action buttons), `CENTER` (editor-specific toolbar), and `RIGHT` (dropdown menus). Buttons are registered dynamically via `Nav.register(config)`, each with a `preconditionFn` that controls visibility. Nav buttons are automatically reflowed into a "more" overflow menu when the window is too narrow.

```js
// Nav scope constants
Nav.Scope = {
    'LEFT':   -1,   // compile, upload, undo, redo
    'CENTER':  0,   // editor-injected toolbar buttons
    'RIGHT':   1    // File / Settings dropdown menus
};
```

## Environment Detection

All environment branching uses the `goog.isElectron` boolean, set once in `common/main.js` by detecting whether `window.process.versions.electron` exists:

```js
// common/main.js — environment detection
goog.NOW_ENV  = window?.process?.versions?.electron ? 'electron' : 'web';
goog.isElectron = goog.NOW_ENV === 'electron';
```

Modules that need platform-specific behavior select their implementation at import time with a single ternary:

```js
// common/app.js — runtime implementation selection
const {
    FS,
    File,
    LibManager,
    ArduShell,
    BU,
    PythonShell,
    Serial
} = goog.isElectron ? Electron : Web;
```

Subsystems that only exist in Electron (e.g., `PythonShell.init()`, `ArduShell.initCompile()`) are guarded by `goog.isElectron` checks in `preconditionFn` callbacks, so web builds silently hide those nav buttons without any branching in component logic.

## IPC: Main Process → Renderer

The Electron main process communicates with renderer processes through Electron's IPC channel named `'command'`. The `sendCommand` function in `main.js` serializes a command object and calls `webContents.send('command', commandStr)` on one or all renderer windows:

```js
// main.js — sendCommand
function sendCommand(commandObj, win = null) {
    let commandStr = '';
    try {
        commandStr = JSON.stringify(commandObj);
    } catch (error) {
        return;
    }
    if (win) {
        win.webContents.send('command', commandStr);
    } else {
        const nowWebContents = webContents.getAllWebContents();
        for (let i in nowWebContents) {
            nowWebContents[i].send('command', commandStr);
        }
    }
}
```

A command object has three fields:

| Field | Type | Description |
|-------|------|-------------|
| `obj` | `string` | Dot-separated path to a `Mixly.*` object on `window` (e.g. `"Mixly.Electron.Serial"`) |
| `func` | `string` | Method name to invoke on that object |
| `args` | `array` | Arguments passed to the method |

USB device plug/unplug events are the primary use case. The `usb-detection` package fires events in the main process; `sendCommand` relays them to the renderer to refresh the serial port list:

```js
// main.js — USB hotplug → serial port refresh
usbDetection.on('add', (device) => {
    setTimeout(() => {
        sendCommand({
            obj: 'Mixly.Electron.Serial',
            func: 'refreshPorts',
            args: [device]
        });
    }, 1000);
});

usbDetection.on('remove', (device) => {
    setTimeout(() => {
        sendCommand({
            obj: 'Mixly.Electron.Serial',
            func: 'refreshPorts',
            args: [device]
        });
    }, 1000);
});
```

Keyboard shortcut handlers in `createWindow` also use `sendCommand` — for example, `CmdOrCtrl+R` dispatches a soft reload through `Mixly.Electron.Loader.reload` rather than calling `win.reload()` directly, which lets the IDE save unsaved files first.

The renderer side listens for these IPC messages in `Mixly.Electron.Events` (`electron/events.js`), which is loaded only in the Electron namespace:

```js
// electron/events.js
ipcRenderer.on('command', (event, message) => {
    const commandObj = Command.parse(message);
    Command.run(commandObj);
});
```

`Command.run` (`common/command.js`) walks the dot-separated `obj` path on `window`, locates the target method, and calls it with the provided args — making the IPC protocol fully data-driven without any hardcoded dispatch tables.

<Note>
The `@electron/remote` module is enabled per-window via `electron_remote.enable(win.webContents)`. This gives renderer code access to `app`, `dialog`, and other main-process APIs through `Mixly.require('@electron/remote')` without additional IPC plumbing.
</Note>
